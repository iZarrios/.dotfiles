# Setting Up NixOS on a New Device

This guide describes how to install this dotfiles repository on a separate
NixOS laptop. It does not replace, convert, or dual-boot the existing Arch
machine. Both machines clone the same Git repository and share application
configuration, while boot, storage, GPU, monitor, and other hardware settings
belong to the individual host.

The examples use:

- Username: `nixos`
- Hostname: `nixos`
- Architecture: `x86_64-linux`
- Time zone: `America/Montreal`
- Repository: `/home/nixos/.dotfiles`

Change those values when a machine needs different ones. Do not copy the Arch
machine's hardware assumptions or another NixOS machine's
`hardware-configuration.nix`.

## What Is and Is Not Shared

The two machines are independent installations:

- Arch continues to use pacman, AUR, and GNU Stow.
- The laptop uses NixOS, flakes, and Home Manager.
- Git-tracked application configuration is shared between them.
- Each operating system has its own package declarations.
- Hardware, boot, services, monitor layout, and power management are configured
  specifically for the laptop.

Changes move between the machines through normal Git commits and pulls. NixOS
does not read files from the Arch machine or require it to be online.

## 1. Install NixOS

Boot the current NixOS installer and connect it to the network. Partition and
format the device using the installation method appropriate for that machine.
Mount the future root filesystem at `/mnt`, and mount the EFI system partition
at the location required by the selected bootloader, normally `/mnt/boot`.

Generate the initial configuration:

```bash
sudo nixos-generate-config --root /mnt
```

Complete a minimal installation using the generated configuration. Create the
`nixos` user during this installation or from the live environment. Make sure
the user can use `sudo` or belongs to `wheel` before relying on the repository.

The first installation only needs to boot, provide networking, and allow the
repository to be cloned. The full desktop can be enabled afterward.

## 2. Record the Device Information

After booting the installed system, collect the details that may affect its
host configuration:

```bash
hostnamectl
lscpu
lspci -k
lsblk -f
findmnt
ip link
systemctl --failed
```

For a Hyprland system, record monitor names, supported modes, and refresh rates
after starting a Wayland session:

```bash
hyprctl monitors all
```

Important device-specific decisions include:

- UEFI versus legacy BIOS
- systemd-boot versus GRUB
- Disk encryption and filesystem layout
- Intel, AMD, NVIDIA, or hybrid graphics
- Laptop power management
- HiDPI scaling and monitor arrangement
- Wi-Fi and Bluetooth firmware

Do not enable a hardware module merely because another host uses it.

## 3. Clone the Dotfiles

Install Git temporarily if it is not already available, then clone the
repository as the target user:

While logged in as `nixos`, run:

```bash
nix-shell -p git --run \
  'git clone https://github.com/izarrios/.dotfiles.git /home/nixos/.dotfiles'
cd /home/nixos/.dotfiles
```

If the repository was cloned as root, correct its ownership before continuing:

```bash
sudo chown -R nixos:users /home/nixos/.dotfiles
```

Replace the clone URL if using a fork or SSH remote.

## 4. Create a Host Configuration

Each device should have its own directory under `hosts`. Start by copying a
minimal host template or the closest existing host:

```text
hosts/
  nixos/
    default.nix
    hardware-configuration.nix
    home.nix
```

Use a unique directory and flake output name when managing multiple devices,
for example `hosts/laptop` and `nixosConfigurations.laptop`. The hostname may
also be unique, but the flake output and hostname do not have to be identical.

Copy the hardware configuration generated by the installer:

```bash
cp /etc/nixos/hardware-configuration.nix \
  /home/nixos/.dotfiles/hosts/nixos/hardware-configuration.nix
```

If preparing the repository from the installer before the first boot, use:

```bash
cp /mnt/etc/nixos/hardware-configuration.nix \
  /mnt/home/nixos/.dotfiles/hosts/nixos/hardware-configuration.nix
```

Review the copied file, but normally retain the generated filesystem,
initrd-module, and CPU settings. Regenerate it after material storage changes:

```bash
sudo nixos-generate-config --show-hardware-config
```

Do not overwrite a reviewed hardware configuration without checking the diff.

## 5. Configure the Host

Set or verify the following values in the host's Nix modules:

- `networking.hostName`
- Username and home directory
- `time.timeZone`
- Bootloader
- Filesystems and swap
- CPU microcode
- Graphics driver
- Network interfaces if NetworkManager is insufficient
- Host-specific services and capabilities

Use `America/Montreal` for the default time zone unless the device is normally
located elsewhere.

Keep `system.stateVersion` at the version used for the machine's first NixOS
installation. Keep `home.stateVersion` at the version used when Home Manager
first managed that account. These values control compatibility defaults; they
are not package release channels and should not be routinely increased.

### Graphics

Start with the simplest applicable graphics configuration:

- Intel or AMD: use the standard NixOS graphics stack first.
- NVIDIA desktop: enable the NVIDIA module only after identifying the GPU.
- Hybrid laptop: determine the integrated and discrete GPU PCI bus IDs before
  enabling PRIME offload.

Find GPU PCI addresses with:

```bash
lspci -D | grep -E 'VGA|3D|Display'
```

Do not reuse PRIME bus IDs from another device.

### Bootloader

For a typical UEFI installation, systemd-boot is the default choice. Use GRUB
when the partitioning, firmware, or multiboot arrangement requires it. Confirm
that the EFI system partition is mounted at the path declared in the Nix
configuration before rebuilding.

## 6. Configure Shared Dotfiles

The files at the repository root and under `.config` are the source of truth
for both Arch Linux and NixOS. Arch deploys them with GNU Stow. Home Manager
links those same sources on NixOS.

Shared application configuration includes, where applicable:

- Zsh, Git, and tmux
- Neovim
- Hyprland
- Noctalia
- Terminal emulators
- btop
- Editors and IDEs
- Scripts under `.local/scripts`

Do not duplicate their settings in `home.nix`. Home Manager should install the
programs and link the shared files, not translate their contents into Nix.

Machine-specific monitor settings should live in a small host-specific file
loaded by the shared `hyprland.lua`. Create that file only after obtaining the
output names from `hyprctl monitors all`.

## 7. Check the Flake

The checked-in lock file predates this redesigned flake and its Hyprland pin is
older than the Lua configuration. Refresh it once during the first laptop
setup:

```bash
nix flake update
```

After committing that refreshed lock file, normal checks and builds should not
update dependencies:

```bash
nix flake check
nix build .#nixosConfigurations.nixos.config.system.build.toplevel
```

Substitute the new host's flake output name for `nixos` when necessary. Commit
`flake.lock` whenever inputs are deliberately updated.

## 8. Test Before Switching

First activate the configuration temporarily:

```bash
sudo nixos-rebuild test --flake /home/nixos/.dotfiles#nixos
```

Check at least:

- The user can log in and use `sudo`
- Networking and DNS work
- Audio devices appear
- Bluetooth works when required
- The graphical session starts
- Displays use safe modes and scaling
- Keyboard input works
- A terminal and editor open
- The previous boot entry still exists

The `test` activation does not make the new generation the default on the next
boot. If the graphical session fails, switch to a TTY with `Ctrl+Alt+F2` or
another available function key and inspect the user journal:

```bash
journalctl --user -b -p warning
sudo journalctl -b -p warning
```

Once the temporary activation is healthy, make it persistent:

```bash
sudo nixos-rebuild switch --flake /home/nixos/.dotfiles#nixos
```

Reboot and verify it once more.

## 9. Validate the Workstation

Verify features in this order so that optional components do not obscure basic
failures:

1. Boot, login, networking, and DNS
2. Hyprland, monitor layout, keyboard, and pointer
3. XDG portals, clipboard, screenshots, and file dialogs
4. PipeWire audio and Bluetooth
5. Zsh, tmux, Git, Neovim, and language servers
6. Tailscale and Docker
7. NVIDIA, CUDA, gaming, libvirt, and Android tooling

Add the final category only after the base desktop is stable.

## 10. Updating the System

Review repository changes before applying them. To update pinned dependencies:

```bash
cd /home/nixos/.dotfiles
nix flake update
nix flake check
sudo nixos-rebuild test --flake .#nixos
sudo nixos-rebuild switch --flake .#nixos
```

Commit the updated `flake.lock` after a successful test.

Home Manager links shared dotfiles directly into `/home/nixos/.dotfiles`, so
editing them takes effect immediately on NixOS just as it does with Stow on
Arch. A rebuild is needed only after changing Nix modules, packages, services,
or the set of managed links.

## 11. Recovery and Rollback

If a test activation is broken, reboot to return to the previous persistent
generation. If a switched generation is broken, select an older generation in
the bootloader or run:

```bash
sudo nixos-rebuild switch --rollback
```

List system generations with:

```bash
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system
```

Never remove old generations until the new configuration has booted and its
networking, display, and input devices have been verified.

## New Device Checklist

- [ ] Install a minimal bootable NixOS system
- [ ] Create the target user with administrative access
- [ ] Record CPU, GPU, disks, network devices, and monitor outputs
- [ ] Clone the dotfiles repository
- [ ] Create a unique host directory and flake output
- [ ] Copy the installer-generated `hardware-configuration.nix`
- [ ] Configure the bootloader and filesystems
- [ ] Configure the correct graphics stack
- [ ] Set hostname, username, home directory, locale, and time zone
- [ ] Add host-specific monitor settings
- [ ] Run `nix flake check`
- [ ] Build the system without activating it
- [ ] Run `nixos-rebuild test`
- [ ] Verify the base desktop and peripherals
- [ ] Run `nixos-rebuild switch`
- [ ] Reboot and confirm rollback remains available
