# Dotfiles

One set of application dotfiles shared by two independent machines:

- Arch Linux installs packages with pacman/AUR and deploys the files with GNU
  Stow.
- The NixOS laptop installs packages and services declaratively, then Home
  Manager links the same tracked configuration files.

The machines synchronize through Git. NixOS does not replace or depend on the
Arch installation.

## Arch Linux

Install the packages listed under `setup`, then deploy the dotfiles from the
repository root:

```bash
./setup/install_deps.sh
stow .
```

The Stow ignore file excludes the NixOS modules and setup documentation.

## NixOS Laptop

Read [nixos.md](./nixos.md) for the complete new-device runbook.

The initial setup is intentionally blocked by
`hosts/nixos/hardware-configuration.nix`. On the new laptop, replace that file
with the configuration generated by the NixOS installer:

```bash
cp /etc/nixos/hardware-configuration.nix \
  ~/.dotfiles/hosts/nixos/hardware-configuration.nix
```

Then validate and temporarily activate the configuration:

```bash
cd ~/.dotfiles
nix flake update
nix flake check
nix build .#nixosConfigurations.nixos.config.system.build.toplevel
sudo nixos-rebuild test --flake .#nixos
```

After verifying networking, graphics, input, audio, and the desktop:

```bash
sudo nixos-rebuild switch --flake .#nixos
```

## Configuration Ownership

Shared application configuration remains in ordinary files such as `.zshrc`,
`.tmux.conf`, `.config/nvim`, and `.config/hypr`. Do not duplicate those
settings in Home Manager.

The desktop shell is native Noctalia v5. Its shared base configuration is
`.config/noctalia/config.toml`; see `.config/noctalia/MIGRATION.md` when removing
the former Quickshell-based v4 packages.

Nix modules own only machine state:

- `hosts/nixos`: laptop identity and installer-generated hardware
- `modules/nixos`: boot, desktop, networking, services, and power management
- `modules/home`: user packages and links to the shared dotfiles

Secrets remain outside the repository in `~/secret.zsh`, which `.zshrc` loads
when present.
